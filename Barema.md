# Barema do Problema 1 - VAIJUNTO: Sistema de Caronas Compartilhadas

Os itens abaixo orientam a elaboração do relatório e a preparação da apresentação. Durante a apresentação, você deverá demonstrar o sistema em funcionamento e será arguido sobre cada um destes pontos.

| # | Item Avaliado | Descrição |
| :--- | :--- | :--- |
| **1** | **Arquitetura** | Explicar os componentes principais do sistema e seus papéis. Descrever como o servidor central mantém o estado das caronas e das reservas, e como os clientes motorista e passageiro se relacionam com ele. Apresentar o modelo de dados adotado para carona, rota, trecho e assento. |
| **2** | **Comunicação** | Descrever a implementação da comunicação entre os componentes, indicando como a biblioteca de sockets (TCP/IP) é utilizada. Explicar como o servidor gerencia as conexões dos clientes e como trata a chegada e a saída de um cliente. Justificar a escolha do protocolo de transporte adotado. |
| **3** | **Protocolo (API Remota)** | Apresentar a especificação completa do protocolo de comunicação implementado. Descrever o formato das mensagens (estrutura, campos, tamanho), o fluxo de conexão e autenticação, as operações disponíveis e as regras de sincronização entre cliente e servidor. Incluir exemplos concretos de mensagens trocadas. |
| **4** | **Encapsulamento** | Explicar como os dados são encapsulados e formatados para garantir sua correta interpretação entre sistemas computacionais distintos. Descrever como são enviados e tratados na chegada (validação, parsing) e como o sistema lida com erros de formato ou dados inválidos. |
| **5** | **Busca de Itinerários** | Descrever como o servidor encontra os itinerários possíveis entre uma origem e um destino. Explicar como trechos de caronas de motoristas diferentes são combinados em um mesmo itinerário e quais critérios foram usados para montar e ordenar as opções apresentadas ao passageiro. |
| **6** | **Concorrência** | Explicar como as requisições simultâneas são gerenciadas e controladas para evitar conflitos. Descrever como o servidor atende vários passageiros e motoristas ao mesmo tempo e como protege as estruturas de dados compartilhadas. Indicar se foi usado algum mecanismo para melhorar o desempenho (threads, thread pool, multiplexação de I/O). |
| **7** | **Atomicidade da Reserva** | Explicar como o sistema garante que a confirmação de um itinerário com vários trechos seja atômica. Descrever o que acontece quando o último trecho não está mais disponível, como as travas dos trechos são adquiridas e liberadas, e como o sistema evita bloqueios mútuos entre passageiros que reservam os mesmos trechos em ordens diferentes. |
| **8** | **Interação** | Descrever como as aplicações cliente foram construídas. No cliente motorista, como se publica uma carona e se acompanham os passageiros confirmados por trecho. No cliente passageiro, como se busca, confirma, consulta e cancela uma reserva. |
| **9** | **Confiabilidade** | Explicar como o sistema lida com falhas. O que acontece se um cliente for encerrado abruptamente no meio de uma reserva? Como o sistema evita que assentos fiquem permanentemente bloqueados? Detalhar o uso de timeouts e o tratamento de exceções nos sockets. |
| **10** | **Testes** | Descrever o teste de software desenvolvido para verificar a validade da solução, com foco em testes automáticos que assegurem a corretude sob concorrência e meçam o desempenho com múltiplos clientes simultâneos. |
| **11** | **Emulação** | Explicar como os componentes do sistema foram desenvolvidos e testados em contêineres Docker, permitindo a execução de múltiplas instâncias no laboratório. Descrever especificamente como foi resolvido o problema de conectividade entre contêineres executados em máquinas distintas. Comentar as vantagens dessa abordagem. |
